# 1.16.0：月度战线与生活事件变化

本版修复两类停滞：战争开始后地图长期维持开局控制；只按“下个月”时一直续写同一件琐事。按用户要求，本轮不运行游戏测试、模拟游玩、浏览器验收或真实模型请求。实际编译、封装与发布状态见 [VERIFICATION.md](VERIFICATION.md)。

## 战争按月推进

- `war-dynamics.js` 在月度预览副本中建立并推进战役，正式提交后随存档保存。阿富汗等 MOD 开局明确交战双方会在相邻行政单位之间进攻、反击或短暂僵持；地图保留拥有者底色和进攻方斜纹。
- 台海战争从梧棲、八里、安南等西岸候选地开始登陆，建立滩头阵地，再向邻近区域推进。后续可开辟其他登陆点，滩头被夺回后可重新组织登陆。登陆不等于整场战争获胜。
- 战况写入独立新闻，控制区与前线同时用于地图、当地制度说明和通行、生活成本等影响；不额外占用个人行动，也不重复结算个人费用。
- 明确接管、停火、国家胜负与既有政治终局优先。整省或全国接管覆盖下属自动模拟记录；单场战斗不会自行推翻已经确定的全国结果。没有开局战争证据的割据地区不会仅因多方控制自动发动全面战争。
- 县级邻接使用现有中心点与包围范围构成抽象地理邻接，不声称是军事史实或精确实测战线。缺少县级数据的国家继续使用已有最细行政层。
- 利比亚与中非缺少明确映射的行政单位，在战役初始化时按距 MOD 已知归属据点的最近距离作一次性连片适配；已有行政单位映射和玩家明确控制记录保持优先。适配方法与 MOD 州文件来源保存在 `warDynamics.campaigns` 对应战役的 `initialAdaptation` 中（`nearest-mod-owned-centre`）。这些分区用于抽象模拟，不代表精确的现实控制线。

## 每个月都有新的经历

- 以 `life-rhythm.js` 保存近期题材、具体已办结事项和限期跟进的未完事项。最近出现的事件、题材和办完的手续降低再次抽中概率；短期等待最多占据两次后续经历，之后暂缓，长期职业与项目仍保留。
- 联网提示直接收到本月抽出的生活事件。只按“下个月”时以新经历为中心，职业、病情和关系作为背景；本人主动行动时仍优先写行动、结果与影响。
- 同一批联络表已经交齐后，不得在下一段又写成尚未提交。对明确的新一批事务保留区别；不把办完一张表等同于结束整个学业或职业。
- 职业场景共 24 条，拘押、服役、公共职务与创作各 6 条；特殊人生场景共 66 条，减少固定检查、交接和觅食段落的重复。被拘押时不安排自由外出，海洋身体不套陆地日常，不凭空生成小游戏收获。
- 新月份保存 `dailyId` 和题材，模型回复不再丢失事件身份。重试、读取和查看地图不重新抽奖或推进月份，旧档从近期经历恢复生活记录，不重写历史正文。
