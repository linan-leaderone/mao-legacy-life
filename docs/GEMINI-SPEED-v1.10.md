# Gemini 请求优化

2026-10-25，本次只改变请求组织方式，继续使用用户选择的地址、协议和模型。指定转发站仍为 `https://aiapi.shiwuyan.cn/v1beta`，模型仍为 `gemini-4-argon`。

## 已落地

- 转发站兼容所需的规则放在用户消息中发送一次，删除此前重复的 `systemInstruction`。其他 Gemini 服务保留系统与用户消息分离。
- 从共用提示生成请求副本，跳过本月未启用的死亡、小游戏、翻译、世界变更或选项规则分支；删除内容完全相同的连续性字段。日期、当前年龄、身份、自定义身体、所在地制度、资金、伤势、行动结果、世界历史、长期记忆、固定事实与 MOD 片段均保留。
- 关系提示保留近期人物、当前行动与续写主线提及的人，以及最强的八组直接关系；不超过 96 条关联边。完整关系图和接触记录继续保存在人生档案中，不因提示裁剪被删除。
- 提醒模型只返回真正新增的记忆、关系与身份变化，区分行动当月的过程和进入下个月的后续，减少无变化字段的复述。
- 仅已验证的指定转发站与 `gemini-4-argon` 使用 `thinkingLevel: low`。没有向未知模型或其他主机加入专有参数，也没有自动改用其他服务。

Google 的 Generate Content 文档说明 Argon 支持 low、medium、high 思考级别，不能完全关闭思考；降低思考级别可减少延迟。`maxOutputTokens` 同时包含思考与输出，盲目降低上限会导致截断，因此仍保留原有的 6,000 上限。转发服务实际接受了 `thinkingLevel: low`，但其是否完整传递上游参数无法从兼容响应中证明。[官方 thinking 文档](https://ai.google.dev/gemini-api/docs/generate-content/thinking)、[Argon 参数说明](https://ai.google.dev/gemini-api/docs/generate-content/latest-model)。

## 实测结果与边界

`node scripts/check-gemini-speed.mjs` 是手动运行的付费对照探针，不属于测试或构建流程。脚本只在本机读取 `.private/settings.json`，不输出凭据；结果只记录数字化用量、请求大小、耗时和虚构样例文本。固定场景是日本的普通角色本月在咖啡店见到美竹兰、约定下月排练。两条请求使用同一角色、行动、地址和模型，并检查咖啡店会面没有被下月排练替代、后续承接音乐安排、实际联系人保留。

| 最终通过样本 | 原版 | 优化版 |
| --- | ---: | ---: |
| 请求大小 | 59,427 字节 | 39,363 字节 |
| 服务报告的输入 token | 13,661 | 9,384 |
| 服务报告的输出 token | 540 | 582 |
| 从发起到校验完成 | 37.3 秒 | 39.8 秒 |
| 请求次数 | 1 | 1 |

输入减少 31.3%，请求字节减少 33.8%。这组实际耗时未缩短，服务排队和上游生成仍存在波动，不能据此保证每月变快。先前探索样本曾出现 12.9 秒与 5.5 秒，但优化样本混淆行动月份；加强日期分工后重新执行以上完整验证，不把探索耗时当作质量合格的提速证明。最终机器可读记录见 `GEMINI-SPEED-v1.10.json`。

API 与压缩专项测试共 28 项通过，覆盖不同协议、原生桥、取消、格式错误、单次文风修订、三分钟总截止时间、日期与身体变化、外文报道、死亡状态、强关系保留及原存档不变。失败和取消继续不提交月份，修订复用同一份行动计算结果；没有增加预生成或后台付费请求。
